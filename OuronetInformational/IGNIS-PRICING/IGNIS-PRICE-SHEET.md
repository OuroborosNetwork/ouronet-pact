# IGNIS PRICE SHEET — per Talos client function, grouped by logical module

Generated by `REPL/_ignis_price_sheet.py` (shares the pricing brain of
`REPL/_ignis_deter_worksheet.py`, so the two sheets cannot drift).

## How to read this

**`TOTAL = deter + components`.** The *deter* column is the deterrence multiplier only —
a "$100 function" means deter = 10000x, i.e. 10000 IGNIS of deterrence. The normal IGNIS
consumption (*components*: writes, updates, reads, scans, cross-module hops) is charged
**on top**, and is what the *components* column shows.

**SIMPLE (fixed price)** — the logic is fixed, so the cost is exactly knowable. These are
the BUILDING BLOCKS every complex function is composed from (flip a boolean, mint a true
fungible, transfer a DPTF …). Their TOTAL is a real, quotable number.

**COMPLEX** — composed of several simple ops in a *varying* composition (a list-driven
loop, per-nonce/per-hop work, a heavy scan). No single total exists, so we print the
**floor**: it costs *at least* the deter price, plus whatever its runtime path consumes.

**EXEMPT** — deliberately free: all Ouronet-Admin `A_*` ops, account deploys, and the
IGNIS machinery itself (the collectors, Compress/Sublimate/Firestarter, DalosFuel).

Each section is one **logical Talos entity**; the rows drop the redundant prefix, so a row
`C_AddHotRBT` under `## ATS` is called as **`ATS|C_AddHotRBT`**. Functions are listed
alphabetically within each module.

Grouping is by **logical Talos entity** — the `ENTITY|fn` prefix — so e.g. `SWP` covers ops
physically spread across SWP / SWPI / SWPLC / SWPU / MTX-SWP. Talos is the only supported
client path, so these are the functions a client actually calls.

*Caveat:* `components` is the modelled compute cost (Option-A buckets, calibrated against
measured gas in rehaul substage 6). It counts the core op's own module-internal work;
cross-module callee internals are not re-summed, so delegating ops read a little low.
