# Deploy/PureV11 — one operation, one event

**3 transactions. Send 01 → 02 → 03 in order.** ~365 KB total, ~2,500 gas in size charges; the
largest single transaction is ~152 KB of the ~395 KB / 2.00M limit. Generated by
`python3 REPL/tools/_purev11.py --write`, manifest by `--multipact`.

| tx | module | bytes | ~size gas | why it ships |
|---:|---|---:|---:|---|
| 01 | **TS02-C3** | 152,417 | 2,139 | the fix — 14 forwarding capabilities lose `@event`, 9 keep it |
| 02 | AQP-INFO | 111,168 | 235 | dot-pin re-pin only (1 call site into TS02-C3) |
| 03 | AQP-BOOT | 101,880 | 128 | dot-pin re-pin only (1 call site into TS02-C3) |

## Why this round exists

Read off the explorer, 2026-10-14, against a real
`ouronet-ns.TS02-C3.AQP-POOL|CC_ReassignTrueFungibleStakeBeneficiary`: **one operation produced
two events.**

```
FVT|C>REASSIGN-TRUE-FUNGIBLE-BENEFICIARY     from AQP-FVT   -- conditions + write live here
AQP|C>REASSIGN-TRUE-FUNGIBLE-BENEFICIARY     from TS02-C3   -- a shell that only forwards
```

Owner ruling, 2026-10-14, verbatim: *"only the function from the module itself has to be
evented ... the evented capability from the talos module is redundant. on the P|TS capability
would have been enough. there was no need to event from the Talos Module."*

### It is not a slip in the three Reassigns — it is the module

The first guess was that this crept in with the Reassign capabilities added days earlier for
V10. It did not. Measured across every Talos module in the tree:

| module | defcaps | evented |
|---|---:|---:|
| **TS02-C3** | 28 | **23** |
| TS01-A, TS01-C1, TS01-C2, TS01-C3, TS01-P, TS01-C4 | 33 | 0 |
| TS02-C1, TS02-C2, TS02-DPAD | 15 | 0 |

TS02-C3 is the only Talos module in Ouronet that events at all — and it already contradicts
itself inside its own file: `AQP-POOL|C_FinalizeVacate` and `AQP-POOL|CC_FullVacate` acquire a
bare `(with-capability (P|TS) ...)`, the correct shape, a few lines from siblings that do not.

## The rule this round applies

Owner ruling, 2026-10-14 — **one evented capability per core function called**:

1. Talos **forwards** to a core function that is already evented → Talos must **not** event.
2. Talos **orchestrates several** evented core functions → still does not event. Several events
   appear, one per real operation; that is not duplication, that is the orchestration.
3. The core function carries **no** evented capability → the Talos capability **is** the single
   event, and stays.

Rule 3 is not a loophole, it is a third of this module. Classifying all 23 against the core
capability each one actually reaches gives a clean split:

### The 14 that lose `@event` (rule 1 — the core already fires one)

| `AQP\|C>REASSIGN-TRUE-FUNGIBLE-BENEFICIARY` | `AQP-FVT::FVT\|C>REASSIGN-TRUE-FUNGIBLE-BENEFICIARY` |

Six of those duplicated even the **name** — `AQP|C>BEGIN-SCORE-REVOKE` and friends are declared
twice in the tree, once in AQP-POOL and once here, so the explorer showed the identical label
twice on one transaction.

### The 9 that keep it (rule 3 — there is no other event)

`STAKE-TRUE-FUNGIBLE`, `UNSTAKE-TRUE-FUNGIBLE`, `STAKE-ORTO-FUNGIBLE`, `UNSTAKE-ORTO-FUNGIBLE`,
`STAKE-SPECIAL-CUSTODIAL`, `STAKE-SEMI-FUNGIBLE-COLLECTABLE`,
`UNSTAKE-SEMI-FUNGIBLE-COLLECTABLE`, `STAKE-NON-FUNGIBLE-COLLECTABLE`,
`UNSTAKE-NON-FUNGIBLE-COLLECTABLE`.

All nine reach one of three core recipes — `FVT|C>TRUE-FUNGIBLE-STAKE-FLOW`,
`FVT|C>ORTO-FUNGIBLE-STAKE-FLOW`, `FVT|C>COLLECTABLE-STAKE-FLOW` — and **none of the three is
evented**. Worse for any "move it down to the core" instinct: each is a single `direction:bool`
recipe shared between a stake and an unstake (and `STAKE-SPECIAL-CUSTODIAL` shares the orto one
with both), so a core event could not name which of the two happened. Stripping these would have
left the entire AQP stake surface with no event at all — the opposite of the ask.

`REPL/tools/_purev11.py` asserts this split **by name, in both directions**, before it will emit
anything: a 15th cap that still events fails the round, and so does a 10th that lost one.

## What ships

Removing `@event` changes no signature, no table and no interface — `defcap`s are not interface
members in this tree, so `TalosStageTwo_ClientThreeV3` is byte-identical to the copy V10 put on
chain and is **not** re-sent (a live interface refuses a re-send). Every source in this round is
`module-only`.

**But TS02-C3 owns tables its dot-callers read.** `python3 REPL/tools/_dotpin.py --upgrade
TS02-C3` is the authority on the round's real size, and it names two:

```
UPGRADING TS02-C3 HARD-BREAKS 2 MODULE(S).
   1_SOVEREIGN/STAGE_02/2_Core/03_AQP/09_AQP-INFO.pact   (1 call site(s))
   2_CITIZEN/5_VaultsMinter/04_AQP-BOOT.pact             (1 call site(s))
```

A dot-pinned caller left on the superseded hash does not go stale, it **aborts** with "hash not
blessed" the next time that path is taken. Neither module has a source change of its own this
round; both are here because 01 moved, and both must land after it.

## No client transaction

Nothing migrates. An event that is no longer emitted needs no backfill, and every event already
recorded on chain stays exactly as it was recorded — this round changes what future transactions
emit, not the history.

