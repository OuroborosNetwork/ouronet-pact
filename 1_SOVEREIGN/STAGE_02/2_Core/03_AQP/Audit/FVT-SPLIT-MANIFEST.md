# FVT-SPLIT-MANIFEST — verified relocation list (P1)

Generated by static call-graph analysis (`REPL/_fvtsplit.py`) over `04_FVT.pact`.
**Key result: 0 functions directly touch both domains** → the seam is clean; no atomic
cross-domain write-transaction needs untangling. All coupling is at the call-graph level.

## Classification (transitive)
| class | count | disposition |
|---|---|---|
| **RPS** (touches only RPS tables, transitively) | 79 | **move to `RPS`** |
| **FVT** (touches only FVT tables) | 164 | stay in `FVT` |

## `XE_` boundary (RPS exposes; FVT calls)
The 77 SEAM orchestrators keep their structure logic and call RPS through `XE_`/reader refs.
The RPS-write portions already isolated in the 79 above become the `XE_` surface. Hot-loop
settle/inject bodies that today read FVT structure per-iteration get the structure **arg-passed**
so the loop runs entirely inside RPS (one hop per phase — §5 of the design).

## DAG check
`RPS` functions directly reading an `FVT` table: **NONE**. `RPS` is a clean leaf →
deploys first. Any exception found during surgery = convert that read to an argument.
